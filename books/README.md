## 책 사이의 연결

- WMS·ERP·OMS·TMS가 정보를 주고받는 실제 사례는 [시스템 컨텍스트 다이어그램](./아키텍트-첫걸음/3-아키텍처-설계/6-아키텍처-문서화.md#시스템-컨텍스트-다이어그램의-예)으로 구조화할 수 있다.
- 입고·출고·재고관리 KPI는 아키텍처에서 말하는 [측정 가능한 품질 속성](./아키텍트-첫걸음/3-아키텍처-설계/2-아키텍처-드라이버의-핵심-사항.md#품질-모델--측정-가능한-속성으로-정의한다)의 도메인 사례로 읽을 수 있다.
- 크로스도킹과 재고보관의 선택은 한쪽이 항상 우월한 문제가 아니라 [아키텍처 트레이드오프](./아키텍트-첫걸음/3-아키텍처-설계/1-아키텍처-설계의-주요-개념.md#아키텍처는-트레이드오프다)와 같은 판단 구조를 가진다.
- 유지보수성이 좋은 코드는 [변화에 대응하는 코드](./내-코드가-불안한-개발자를-위한-좋은-코드의-기준/01-왜-좋은-코드를-작성해야-할까/1-변화에-대응하는-소프트웨어.md)이며, 아키텍처의 [어질리티](./아키텍트-첫걸음/1-아키텍트가-하는-일/2-어질리티-변화에-대한-적응-능력.md)를 코드 수준에서 뒷받침한다.
- [기술 부채](./내-코드가-불안한-개발자를-위한-좋은-코드의-기준/01-왜-좋은-코드를-작성해야-할까/3-기술-부채.md)를 기록하고 갚는 판단은 [아키텍처 의사결정 기록](./아키텍트-첫걸음/3-아키텍처-설계/5-아키텍처의-비교-평가.md#아키텍처-의사결정-기록)과 함께 읽을 수 있다.
- [뜻을 전하는 이름](./내-코드가-불안한-개발자를-위한-좋은-코드의-기준/02-움직이는-코드에서-뜻을-전하는-코드로/2-이름-짓기.md)과 [유비쿼터스 언어](./내-코드가-불안한-개발자를-위한-좋은-코드의-기준/02-움직이는-코드에서-뜻을-전하는-코드로/4-코드로-도메인-지식-표현하기.md#유비쿼터스-언어를-찾는다)는 물류 기준정보의 [일관된 코드 설계](./wms-원리와-이해/03-기준정보/5-코드의-효율적인-설계와-운영.md)와 연결된다.
- WMS의 입고·재고·출고 경계는 [재고 도메인 모듈을 분리한 실제 사례](./요즘-우아한-백엔드-개발/02-전체-서비스를-관통하는-도메인-모듈-안전하게-분리하기/README.md)에서 코드 구조와 배포 전략으로 이어진다.
- WMS의 출고가능 체크·피킹·배차는 [B마트 OMS가 피크를 분산하고 동적으로 출고 시각을 계산한 사례](./요즘-우아한-백엔드-개발/11-b마트-oms의-물류주문관리를-통한-출고-최적화/README.md)에서 주문 오케스트레이션과 시뮬레이션으로 확장된다.
- WMS의 재고이동·할당은 [이관 할당과 취소가 경쟁한 사례](./요즘-우아한-백엔드-개발/13-wms-재고-이관을-위한-분산-락-사용기/README.md)에서 분산 락의 범위·대기 시간·병렬성 트레이드오프로 이어진다.
- 공통 오류 처리의 위치와 책임은 [IllegalArgumentException을 일괄 400으로 매핑할 때의 위험](./요즘-우아한-백엔드-개발/24-illegalargumentexception은-400-bad-request인가/README.md)에서 HTTP 상태 코드·모니터링·커스텀 예외 설계로 구체화되고, [에러 시나리오와 프로그래밍 가능한 진단](./ai-시대의-엔지니어링-전략/03-에러와-경고/README.md)으로 사용자 맥락과 복구 행동까지 확장된다.
- 요구사항의 유저 스토리와 유스케이스는 [동기·페르소나·시뮬레이션으로 구성한 프로덕트 시나리오](./ai-시대의-엔지니어링-전략/01-프로덕트-사고의-기본/README.md)를 통해 사용자 현실과 제품 의사 결정까지 확장된다.
- 코드 안에서 [뜻을 전하는 이름](./내-코드가-불안한-개발자를-위한-좋은-코드의-기준/02-움직이는-코드에서-뜻을-전하는-코드로/2-이름-짓기.md)을 고르는 원칙은 제품 안의 [발견·이해·사용 여정과 기표](./ai-시대의-엔지니어링-전략/02-제품-내-사용자-안내/README.md)로 확장된다.
