# 로케이션과 존

> [WMS 주요 프로세스](./README.md)

## 빠른 복습

- WMS는 **로케이션(Location)이라 칭하는 주소 체계**를 기반으로 재고를 보관한다. 셀(Cell), 빈(Bin), 주소(Address)로 부르기도 한다.
- 로케이션 주소 체계는 각 창고의 환경이나 제품 특성 등을 고려해 구성한다.
- 로케이션을 **업무 특성별로 묶은 것이 존(Zone)**이다. 구역(Area), 섹션(Section)으로도 불린다.
- 자주 쓰는 존은 입고·보관·피킹·출고이고, 필요에 따라 작업·분배 존을 부가적으로 둔다. 관리자가 상황에 맞게 새로운 존을 만들 수도 있다.
- 입고·출고 존은 **차량 진입과 상하차**를 기준으로, 보관존은 **보관과 작업 효율**을 기준으로 설계한다.

## 로케이션 — 재고를 담는 주소

WMS는 통상 "로케이션(Location)"이라 칭하는 주소 체계를 기반으로 재고를 보관한다. 같은 것을 셀(Cell), 빈(Bin), 주소(Address) 등의 용어로 부르기도 한다.

주소 체계는 어느 창고나 똑같은 것이 아니라, 각 창고의 환경이나 제품 특성 등을 고려하여 구성된다.

## 존 — 로케이션의 묶음

로케이션들은 다시 **업무 특성별로 묶여 존(Zone)을 구성**한다. 존은 구역(Area), 섹션(Section) 등으로도 불린다.

## 주요 존의 종류

WMS에서는 입출고 등의 업무를 위해 "입고", "보관", "피킹", "출고" 등의 존을 구성하는 경우가 많다. 경우에 따라 유통가공이나 크로스도킹 등의 작업을 위한 "작업", "분배" 존을 부가적으로 설정해 운영한다. 이 외에도 관리자가 상황에 맞게 새로운 존을 설정하여 운영할 수 있다.

## 존의 배치

```mermaid
%% lint: layout
flowchart LR
    IN["입고존"]
    subgraph CORE["창고 중앙"]
        direction TB
        A["보관존 A"]
        B["보관존 B"]
        C["보관존 C"]
        WK["작업존"]
        DS["분배존"]
    end
    PK["피킹존"]
    OUT["출고존"]

    IN ~~~ CORE
    CORE ~~~ PK
    PK ~~~ OUT

    classDef dock fill:#5b8fc9,stroke:#3f6d9e,color:#ffffff

    classDef pick fill:#3f9e6b,stroke:#2c7a52,color:#ffffff
    classDef work fill:#8a8f8a,stroke:#6a6f6a,color:#ffffff
    class IN,OUT dock
    class A,B,C store
    class PK pick
    class WK,DS work
    style CORE fill:none,stroke:#9aa0a6,stroke-dasharray: 4 4
```

*[그림 2-2] WMS 주요 존(Zone) 운영 예시 — 좌측 입고존에서 우측 출고존으로 이어지는 배치*

이 도식은 **배치**를 나타낸 것이므로 화살표를 넣지 않았다. 재고가 존 사이를 어떻게 흐르는지는 [프로세스 지도](./README.md#모든-업무는-로케이션에서-로케이션으로)에서 확인한다. 색은 원서 [그림 2-2]를 따랐다.

## 존을 설계할 때의 기준

- **입고 및 출고 존** — 차량의 진입과 상하차가 용이하도록 설계한다.
- **보관존** — 재고를 보관하거나 입출고 작업 효율을 높일 수 있도록 다양한 설비(파레트랙 등)를 활용하여 구성한다.

## 함께 읽기

- 존 사이를 재고가 어떻게 오가는지는 [입고와 적치](./2-입고와-적치.md)부터 순서대로 이어진다.
- 로케이션 관리가 총량관리와 무엇이 다른지는 [로케이션 관리](../01-wms-개요/3-WMS의-주요-특징.md#1-로케이션-관리)를 참고한다.
