# 피크매니지먼트 — 기획 방향

> [B마트 OMS의 물류주문관리를 통한 출고 최적화](./README.md)

## 빠른 복습
- **예약 배달**은 **고객이 원하는 시간 안에 도착해야 하는 요구사항이 강한 형태의 주문**이다.
- 문제는 부하의 쏠림이다 — **피크 시간에는 주문이 집중되어 출고가 지연되고, 주문이 적은 시간에는 유휴 인력이 생긴다.**
- 해결의 착상은 하나다. **예약 배달 주문의 출고 요청을 유휴 시간대에 미리 분산 처리한다.**
- 그러면 **피크 시간의 부하가 줄고 시간대별 부하가 고르게 되어, 동일 수준의 인원으로 더 많은 주문을 제시간에 처리**할 수 있다.
- 단 **고객의 희망 수령 시각은 절대적으로 보장**하면서 현장 효율을 높이는 방향으로 구조를 설계했다.
- 핵심 설계는 **출고 요청과 배달 요청의 분리**, **품질 보존을 위한 분산 구간의 정의**, **현장 여유 판단 로직**, **재고 부족 주문의 보존**이다.

## 왜 예약 배달이 기회인가

**즉시 배달 주문은 미룰 수 없지만, 예약 배달 주문은 "언제까지"만 지키면 된다.** 이 여유가 곧 분산의 재료다.

```mermaid
flowchart LR
    ORDER["예약 배달 주문"]
    IDLE["유휴 시간대에<br/>출고 요청 분산"]
    PEAK["피크 시간대<br/>부하 감소"]
    CAP["같은 인원으로<br/>더 많은 주문 처리"]

    ORDER --> IDLE
    IDLE --> PEAK
    PEAK --> CAP

    %% lint-ok: DEAD-END  분산이 만들어내는 결과까지의 흐름이므로 마지막 노드에서 나가는 흐름이 없다
    classDef core fill:#93ad70,stroke:#5f7a44,color:#121a08
    classDef sys fill:#e9e5a8,stroke:#a99f4d,color:#26240c
    class ORDER,IDLE core
    class PEAK,CAP sys
```

*예약 배달 주문의 시간 여유를 현장 부하를 고르게 만드는 데 쓴다*

## 출고 요청과 배달 요청을 분리한다

| | 출고 요청과 배달 요청 |
| --- | --- |
| **AS-IS** | **출고 요청과 배달 요청이 동일 기준으로 산정**됨 |
| **TO-BE** | **출고는 여유가 있는 시간에 처리, 배달은 고객 수령 희망 시각에 맞춤** |

표를 읽는 법. **하나의 시각으로 두 가지를 정하고 있던 것이 문제의 뿌리**였다. 두 요청을 떼어놓는 순간 출고 시각은 **현장이 정할 수 있는 변수**가 되고, 배달 시각은 **고객이 정하는 상수**로 남는다.

## 품질 보존을 위한 분산 시점

분산은 무제한이 아니다. **냉장 보관이 가능함에도 일찍 출고된 상품은 신선도 저하가 우려**되기 때문에, **출고 요청 분산의 시작 시점과 종료 시점을 명확히 정의**했다.

```mermaid
flowchart LR
    START["분산 시작 시점"]
    WINDOW["분산 가능 구간"]
    END["분산 종료 시점"]
    WISH["고객 희망 수령 시각"]

    START --> WINDOW
    WINDOW --> END
    END --> WISH

    %% lint-ok: DEAD-END  구간의 양 끝을 보여주는 도식이므로 마지막 노드에서 나가는 흐름이 없다
    classDef core fill:#93ad70,stroke:#5f7a44,color:#121a08
    classDef sys fill:#e9e5a8,stroke:#a99f4d,color:#26240c
    classDef muted fill:#dcdcd2,stroke:#a8a89c,color:#3a3a30
    class WINDOW core
    class START,END sys
    class WISH muted
```

*분산은 신선도가 허용하는 구간 안에서만 일어난다*

**"너무 일찍"도 품질 저하**라는 것이 이 대목의 요점이다. 최적화의 자유도에 **상품 품질이라는 상한**이 걸린다.

## 현장 여유 판단 로직 고도화

> **목표 생산성을 기준으로 작업 인원 수와 현재 출고량을 비교**해, **실시간 현장 작업의 여유 상태를 판단하는 로직**을 도입했다.

"유휴 시간대"라는 말이 **시계로 정해지는 것이 아니라 계산되는 것**이라는 뜻이다. 같은 오후 3시가 어느 지점에서는 여유이고 어느 지점에서는 피크일 수 있다.

## 재고 부족 방지와 주문 보존

**입고 예정 상품을 포함한 주문이 예약 배달 주문으로 많이 들어올 때가 있다.** 이 때문에 **출고 직전에 재고 부족이 발생할 수 있다.** 그래서

> **재고 부족 주문은 일단 스킵하고, 고객 희망 시간 내에 배송할 수 있는 마지막 시점에 출고 요청되도록** 설계했다.

**분산의 목적이 "빨리 내보내기"가 아니라 "제때 내보내기"** 이므로, 지금 못 나가는 주문은 **버리지 않고 마지막 기회로 미룬다.** 재고를 앞당겨 확인하는 대신 **판단 시점을 늦추는** 선택이며, 이는 OMS가 [가용 재고·입고 예정 재고·할당 재고를 함께 보는 시스템](./README.md)이기에 가능하다.
