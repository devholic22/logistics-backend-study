# 전체 서비스를 관통하는 도메인 모듈 안전하게 분리하기

## 무엇을 한 이야기인가

**B마트 물류 플랫폼의 WMS를 담당하는 WMS 플랫폼 팀이, 하나의 모놀리스(`domain-wms`)에 뭉쳐 있던 입고·재고·출고 도메인에서 재고 도메인을 떼어낸 기록**이다. 그것도 **서비스를 멈추지 않고, 새 기능을 계속 추가하면서** 했다.

> **서비스가 성장함에 따라 도메인은 비대해진다.** 특정 기능 하나를 수정하기 위해 **관련 없는 코드까지 들춰보게** 되고, **사소한 수정에도 예기치 못한 장애가 발생하면 '건드리면 안 되는 코드'** 가 된다.

> 이런 문제는 보통 **하나의 도메인이 지나치게 많은 책임을 지고 있을 때** 발생한다. **코드가 복잡해진 걸 넘어 시스템 전체의 복잡도가 임계점을 넘은 것**이기도 하다.

```mermaid
flowchart LR
    S1["Step 1<br/>도메인 간 결합 끊기"]
    S2["Step 2<br/>모듈 내부 응집도 높이기"]
    S3["Step 3<br/>안전하게 배포하기"]

    S1 --> S2
    S2 --> S3

    classDef core fill:#93ad70,stroke:#5f7a44,color:#121a08
    classDef sys fill:#e9e5a8,stroke:#a99f4d,color:#26240c
    class S1,S2 core
    class S3 sys
```

*결합을 끊고(밖), 내부를 정돈하고(안), 그것을 무사히 내보낸다*
