# 에러와 경고

> [AI 시대의 엔지니어링 전략](../README.md)

## "PC Load Letter? 도대체 이게 무슨 소리야?"

영화 <오피스 스페이스(1999)>에서 **마이클 볼턴이 고장 난 프린터 앞에서 외친 한마디**다. **이 장면 하나로 영화는 형편없는 에러 메시지를 내보내는 기술 업계를 통째로 조롱**했다.

> **소비자는 알아듣기 힘든 진단 에러와 경고를 매일 만납니다.** 전문가도 혼란스러운 메시지에 매달려 몇 시간을 허비합니다. 사용자는 흔히 **'이탈 위험군flight risk'** 입니다. **작은 마찰만 생겨도 우리 제품을 떠나버린다**는 뜻이죠.

> [!IMPORTANT]
> **진단은 제품을 차별화한다**
>
> 엔지니어는 에러와 메시지를 그저 '엣지 케이스'로 취급하기 쉽다. 하지만 진단은 **제품을 차별화하는 핵심이며 장인 정신이 드러나는 부분**이다.

## 이 장이 겨냥하는 두 질문

LaTeX에서 아래처럼 쓰면

```text
This is some text. \\

This is at the end of a block of text. \\

This is the start of a new paragraph
```

이런 경고가 돌아온다.

```text
Underfull \hbox (badness 10000) in paragraph on line 2.
```

*원서 예시 — 뜻은 "2번째 줄 끝의 불필요한 줄바꿈(`\\`)을 빈 줄 앞에서 지우라"는 것이다*

> 메시지가 정말 알쏭달쏭합니다. 다만 **에러를 던지는 코드 위치에서 보면 '바텀업bottom-up' 관점으로는 완벽하게 말이 됩니다.** 코드 구조 때문에 고치기도 만만치 않을 거예요.

- **구현자에게 말이 되는 메시지와 사용자에게 말이 되는 메시지, 둘 사이의 간극을 어떻게 좁힐까?**
- **그 일을 해내려면 코드를 어떻게 짜야 할까?**

가벼운 문제가 아니다. **LaTeX는 인기 언어 순위 40위에 머물지만, 커뮤니티 사이트에서 가장 인기 있는 'underfull hbox' 질문은 조회수 35만 회**를 넘는다. **한 사람이 원인 파악에 3분만 쓴다고 잡아도 LaTeX 저자들은 약 2만 시간을 인류에게 돌려줄 수 있었다.** **더 나은 경고 메시지 한 줄만으로**, 혹은 **그 불필요한 줄바꿈을 그냥 허용하기만 했어도**.

## 반대편 — 진단은 즐거울 수도 있다

구글의 **'Did you mean(혹시 이걸 찾으셨나요)?'** 는 두 가지를 한다.

- **사용자가 무엇을 했는지 보여준다** — 'compture'를 검색했다.
- **다음 행동을 제안한다** — 가장 흔한 맞춤법 수정안으로 가는 링크.

> **검색어를 반복하는 앞쪽 기능은 만들기 쉽지만 사려 깊습니다.** 사용자가 **다른 일을 하다 브라우저 탭으로 돌아온 상황까지 챙긴** 셈이거든요. 뒤쪽 기능은 **구글이 수천만 달러를 들여 만들고 운영해 온 기능**입니다. **엣지 케이스 하나에 이 정도를 쏟은** 겁니다.
