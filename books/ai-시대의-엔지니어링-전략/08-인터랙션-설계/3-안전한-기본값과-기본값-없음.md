# 안전한 기본값과 기본값 없음

> [인터랙션 설계](./README.md)

## 빠른 복습
- **잘 설계된 제품은 생산적이고 안전한 어포던스를 기표화하고 기본값으로** 둔다. **그러면서 사람들이 더 위험한 쪽으로 실수로 빠지지 않게** 막는다.
- **어포던스는 교통 신호처럼 어느 정도 환영받는지를 나타낼 수** 있다 — **녹색은 안전하고 일반적으로 효과적**, **노란색은 주의가 필요함**, **빨간색은 금지됨.**
- **녹색 시나리오는 매우 발견하기 쉽게, 노란색과 빨간색은 덜 발견되게 만든 제품은 쓰는 맛이 좋다.**
- 사용자를 유용한 어포던스로 이끄는 기법은 넷 — **안전하고 예측 가능한 기본값 설정**, **최소 저항 경로 최적화**, **올바른 페르소나에게 올바른 시나리오에서 어포던스 제시**, **검증 수행**.
- **가장 간과되는 기본 설정 중 하나는 '기본값 없음'** 이다.

> [!IMPORTANT]
> **기본값 없음도 설계 선택입니다**
>
> 잘못된 선택의 피해가 크거나 늦게 드러난다면 편의적인 기본값 대신 사용자가 의식적으로 결정하게 해야 합니다.

## 신호등으로 나눈 어포던스

**수상해 보이는 웹 URL 링크를 클릭하는 경우**의 예다.

| 등급 | 상황 |
| --- | --- |
| **녹색** | **같은 사이트 안의 다른 페이지로 이동** |
| **노란색** | **같은 사이트 바깥 페이지로 보낸다.** **"정말로 외부 사이트로 가시겠습니까" 같은 경고**가 뜰 수 있다 — **출처 사이트를 사칭한 사이트로 빠지는 일을 막기** 위해서 |
| **빨간색** | **유효한 보안 인증서가 없는 의심스러운 사이트로 이어지는 링크.** **브라우저는 이동 전에 높은 턱**을 세운다 |

표를 읽는 법. 세 등급이 **금지 여부가 아니라 마찰의 크기**로 갈린다. 그리고 넷째 선택지가 있다 — **아예 어포던스를 빼버릴 수도** 있다. **클릭하려는 웹 페이지가 악성으로 알려져 있다면 브라우저는 이를 통째로 막는다.**

*마찰의 세기로 늘어놓은 네 단계*

> **사용자는 자신 있게 나아가며 제품에 신뢰를 쌓고, 두 번 생각하지 않고도 작동**시킵니다.

**각주로 붙은 표현이 좋다** — **2003년 리코 마리아니가 만든 '성공의 구덩이pit of success'** 는 **사용자가 "자연스럽게 이기는 실천으로 빠지도록" 돕는 기법**을 가리킨다.

## 좋은 기본값

> **대중에게는 적절한 기본 설정을 제공하고, 세부 조정을 원하는 사용자에게는 커스터마이징 기능을 제공**함으로써 **유연성과 사용 편의성의 균형**을 맞추세요.

> **사용자는 제품 개발자가 좋은 기본 설정을 선택해 줄 것이라고 믿고, 그 대가로 제품을 사용하고 비용을 지불**합니다.

**EntSchema는 데이터베이스 칼럼 이름을 스키마 작성자가 지정한 이름과 똑같이 쓴다고 가정**하되, 커스터마이징은 가능하게 했다.

```python
"posted_at": integer_field().db_config(name="created"),
```

*코드에서는 `posted_at`, 데이터베이스에는 기존 이름 `created` 그대로*

> **유연하지만, 모든 작성자에게 데이터베이스 이름을 굳이 지정하게 하지는 않습니다. 코드에서 쓰는 이름을 바꿀 때마다 데이터베이스 마이그레이션을 요구하지도** 않고요.

## 잘못된 기본값의 대가

> **기본값은 단순한 편의성을 넘어서는 의미**를 지닙니다. **잘못된 기본값이 일으킬 파장은 정치적으로 골치 아프거나, 심하면 재앙**이 될 수 있습니다.

- **MS, 애플, 구글 같은 OS 회사는 특정 브라우저나 검색 엔진을 기본값으로 두었다는 이유로 소송**에 휘말렸다.
- **인터넷 익스플로러 초기 버전은 ActiveX 컨트롤을 기본으로** 켰다. **큰 보안 취약점을 만들어 각종 바이러스와 웜이** 퍼졌다.
- **2009년 페이스북은 새 게시물 프라이버시를 '전체 공개'로 기본 설정**하기 시작했다. **큰 반발과 신뢰 하락**이 따라왔고, **이후 사용자에게 더 명시적 통제권을 줬지만 여운은 길게** 남았다.

## 기본값 없음

> **개발자는 호출부를 간결하게 유지하고 제품 인터페이스를 깔끔하게 만들기 위해 모든 항목에 기본 인수를 제공하는 데 익숙**합니다. **하지만 이는 잘못된 균형일 수** 있습니다. **다른 선택지가 안전하지 않거나, 예상과 다르거나, 효과적이지 않을 가능성이 있다면 사용자가 의식적으로 결정하도록** 해야 합니다.

> **자율주행차가 좌회전이나 우회전을 기본값으로 선택하지 않는 것처럼, 목적지를 입력하도록 요구하고 이를 바탕으로 주행 방향을 결정**해야 합니다.

> **제품 인터페이스의 품질은 그것이 사용자에게 던지는 질문의 적절성으로 잴 수 있습니다.**

### EntSchema의 코로케이션

**데이터베이스에 샤드가 여러 개인데, 흔한 쿼리는 '이 작성자의 최근 게시물 전부 가져오기'** 다.

| 상황 | 결과 |
| --- | --- |
| **게시물이 여러 샤드에 흩어짐** | **모든 샤드에 팬아웃해 게시물을 찾아야 하니 엄청나게 비싸다** |
| **게시물이 모두 같은 샤드에** | **쿼리는 잘 동작한다** |

```python
def db_config() -> DatabaseConfig:
    return (DatabaseConfig()
            .name("posts")
            .colocateWith("author"))
```

*작성자는 코로케이션을 반드시 지정해야 한다*

> **EntSchema가 코로케이션 미지정을 '코로케이션 없음'으로 해석했다면, 게시물은 무작위로 흩어졌을** 겁니다. **작성자는 프로덕션에 가기 전, 어쩌면 스케일에 닿기 전까지는 실수를 알아채지 못했을** 거고요. **그래서 기본값을 두지 않아야 합니다. 사용자에게 선택을 강제하고, 트레이드오프를 가능한 한 잘 알려야** 해요.

**기본값이 위험한 조건이 여기 다 들어 있다** — **잘못돼도 즉시 드러나지 않고**, **드러날 때는 이미 되돌리기 어렵다.** [3.7 시프트 레프트](../03-에러와-경고/7-조기-진단-시프트-레프트.md)의 반대 상황, 즉 **피드백이 가장 늦게 오는 종류의 실수**다.
