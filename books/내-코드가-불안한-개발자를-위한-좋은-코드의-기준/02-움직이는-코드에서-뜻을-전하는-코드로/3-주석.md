# 주석

> [움직이는 코드에서 뜻을 전하는 코드로](./README.md)

## 빠른 복습
- **코드만으로 충분히 의도를 파악할 수 있다면 주석을 달지 않아도 된다.** `update()` 위의 "업데이트하기"는 필요 없다.
- **주석도 코드처럼 작성 후 유지보수해야 한다.** 그래서 없어도 되는 주석은 비용이다.
- 반대로 **코드만으로는 전하기 어려운 정보(배경지식)** 는 적극적으로 남긴다.
- **URL만 남기는 것은 지양한다.** 링크가 깨지면 전하려던 내용을 알 수 없으므로 **간단한 내용도 함께** 적는다.
- **행위가 주 목적인 함수**는 이름을 행위로 짓고 **반환값의 뜻은 주석으로 보충**한다.
- 주석으로 보충할 대표적인 것들 — **반환값 · 오류 처리 · null의 의미 · 입력값의 제약 · 입출력 예시**.

## 달지 않아도 되는 주석

```kotlin
/**
 * 업데이트하기
 */
fun update() { ... }
```

> 이럴 때는 **주석을 굳이 안 달아도 된다.** **주석도 코드처럼 작성 후 유지보수해야 한다.** **코드만으로 충분히 의도를 파악할 수 있다면 주석을 달지 않아도 된다.**

**주석이 유지보수 대상이라는 점**이 판단 기준이다. 함수 이름을 그대로 옮긴 주석은 **정보를 주지 않으면서 고쳐야 할 대상만 늘린다.** 이름을 바꿀 때 주석도 같이 바꿔야 하고, 안 바꾸면 **거짓 정보**가 된다.

## 코드로 전할 수 없는 배경지식

> **의도를 코드로 표현하려 해도 코드만으로는 전하기 어려운 정보(배경지식)가 있을 수 있다.**

```kotlin
fun fetch(): Data {
    // Api.call은 올바른 값을 반환하지 않으므로
    // Api.call2를 이용함
    // Issue: #1024
    return Api.call2()
}
```

> **URL만 주석으로 남기는 건 지양한다.** **링크가 깨지면 전하려는 내용이 뭔지 알기 어렵다.** URL을 주석으로 남길 때에는 **간단한 내용도 남기자.**

성능을 이유로 코드를 새로 작성할 때도 마찬가지다. **의문을 줄이기 위해** 남기는 경우가 있다 — **이 코드가 없어도 동작할 것 같은데 왜 추가했는가**에 대한 답이다.

```kotlin
fun calculateArea(shape: Shape): Int {
    // 사각형 넓이는 간단하게 계산할 수 있으므로 먼저 계산하고 반환한다.
    if (shape is Rectangle) {
        return shape.width * shape.height
    }
    // 도형을 그리고 칠한 다음, 채운 픽셀을 센다. (시간이 걸리는 처리)
}
```

**"왜 이렇게 했는가"** 를 남긴다는 점에서 이 주석은 [『아키텍트 첫걸음』 3.5의 ADR](../../아키텍트-첫걸음/3-아키텍처-설계/5-아키텍처의-비교-평가.md#아키텍처-의사결정-기록)과 같은 역할을 한다. 규모만 다르다 — **ADR이 아키텍처의 결정을 남긴다면, 이 주석은 한 함수의 결정을 남긴다.** [1장에서 "개발 시점에 이해한 내용을 코드에 반영해두라"](../01-왜-좋은-코드를-작성해야-할까/3-기술-부채.md#기술-부채를-대하는-자세)고 했던 것의 구체적인 수단이기도 하다.

## 반환값을 보충한다

```kotlin
fun purchase(product: Product): Boolean {
    return try {
        api.purchase(product)
        true
    } catch (e: NetworkException) {
        false
    } catch (e: ServerException) {
        false
    }
}
```

> **반환값의 뜻을 정확히 이해하려면 함수 내용을 전부 확인해야 한다.** 반환값을 주석으로 보충하면 **읽는 시간을 줄일 수 있다.**

```kotlin
/**
 * 지정한 [product]를 구매한다.
 * 구매가 정상적으로 완료되면 true를,
 * 네트워크 오류나 서버 오류가 발생하면 false를 반환한다.
 */
fun purchase(product: Product): Boolean {
    ...
}
```

> **함수 이름으로 동작과 반환값까지 설명될 수 있다면 베스트**이지만, **행위가 주 목적인 함수(`purchase`)는 행위를 중심으로 이름을 지어야 한다.** 함수 이름으로 **반환값까지 억지로 설명하려 하면 이름이 길어지고 부자연스러워져 의미를 알 수 없게 된다.** 이럴 땐 **주석으로 필요한 내용을 보충**하자.

## 오류·null·제약·예시

**오류 처리도 마찬가지다.**

```kotlin
/**
 * [id]로 사용자를 검색하고 찾았다면 해당 사용자를 반환한다.
 *
 * 사용자를 찾지 못하거나 이미 삭제되었다면
 * [IllegalStateException]이 발생한다.
 */
fun getUser(id: String): User { ... }
```

**값이 없음을 나타내는 `null`** 도 뜻을 적어준다.

```kotlin
/**
 * [id]로 사용자를 검색하고 찾았다면 해당 사용자를 반환한다.
 *
 * 사용자를 찾지 못하거나 이미 삭제되었다면 null을 반환한다.
 */
fun findUser(id: String): User? { ... }
```

두 예제의 **함수 이름이 `getUser` 와 `findUser` 로 다르다**는 점을 눈여겨본다. **예외를 던지는 쪽은 `get`, 없을 수 있어 null을 반환하는 쪽은 `find`** 다. [앞 절의 이름 짓기](./2-이름-짓기.md)가 여기서 반환 방식까지 구분해준다.

**입력값에 제약이 있을 때**도 유용하다.

```kotlin
/**
 * [minInclusiveAge] 세 이상 [maxInclusiveAge] 세 이하의 사용자를 반환한다.
 *
 * 결과에는 [minInclusiveAge] 세이고 동시에 [maxInclusiveAge] 세인
 * 사용자를 포함한다.
 * [minInclusiveAge]와 [maxInclusiveAge]는 0 이상 100 이하의 정수로,
 * [maxInclusiveAge] 쪽이 더 크거나 같아야 한다.
 * [minInclusiveAge]와 [maxInclusiveAge]가 같은 정수일 때는
 * 해당 나이의 사용자만 반환한다.
 */
fun searchUsers(minInclusiveAge: Int, maxInclusiveAge: Int): List<User> { ... }
```

**인자 이름에 이미 `Inclusive` 가 들어 있는데도 경계 조건을 다시 설명한다**는 점이 요점이다. **경계는 이름만으로 오해를 없애기 어렵다.**

**입력이나 출력이 복잡할 때는 예를 들어도 좋다.**

```kotlin
/**
 * 문자열 안에서 HH:mm 형식 시각을 찾아 이를 반환한다.
 *
 * 발견하지 못하면 null을 반환한다.
 * 여러 개를 발견했다면 가장 먼저 찾은 것만 반환한다.
 *
 * 예: "지금은 12:34입니다. 10분 후는 12:44입니다." -> "12:34"
 */
fun findTimeString(target: String): String? {
    ...
}
```

| 무엇을 보충하는가 | 왜 코드로는 부족한가 |
| --- | --- |
| **반환값** | 함수 전체를 읽어야 true/false의 뜻을 알 수 있다 |
| **오류** | 어떤 예외가 언제 발생하는지는 호출부에서 보이지 않는다 |
| **null** | 자료형은 `User?` 만 알려주고 **왜 null인지**는 말하지 않는다 |
| **입력 제약** | 경계 포함 여부, 값의 범위, 두 인자의 관계 |
| **예시** | 규칙을 문장으로 읽는 것보다 **한 줄 예시가 빠르다** |

표를 읽는 법. 다섯 항목 모두 **"코드를 다 읽으면 알 수 있지만, 그러려면 시간이 든다"** 는 공통점이 있다. 주석의 값은 **정보의 유무가 아니라 읽는 시간의 절약**에 있다.

## null 허용 자료형

```kotlin
var nonNullString: String = null   // null 값을 허용하지 않는 자료형 = 컴파일 오류
var nullableString: String? = null // null 값을 허용하는 자료형
```

**코틀린은 null 허용 여부를 자료형으로 구분**한다. 그래서 **"null이 올 수 있는가"는 주석이 아니라 자료형이 답한다.** 주석이 맡을 것은 [앞 절에서 "자료형으로 알 수 있는 정보는 생략한다"](./2-이름-짓기.md#너무-긴-이름)고 했던 그 경계 바깥 — **null이 어떤 상황을 뜻하는지**다.
